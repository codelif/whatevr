Compact Parity Checklist
- [ ] App shell routes correctly: login, daemon status, chats, and logout.
- [ ] Header is functional, not branded: chats title, logout, reconnect/refresh only when useful.
- [ ] Responsive layout works: two-pane desktop, chat-list-to-conversation navigation on narrow widths.
- [ ] Chat list is fast and stable with real data, live updates, selection preservation, unread badges, avatars, and one-line ellipsized previews.
- [ ] History sync progress is compact and accurate using only available daemon/proto fields.
- [ ] Conversation view loads messages for selected chat, handles loading/empty/error states, and ignores stale responses after fast chat switching.
- [ ] Message list is virtualized, scroll-stable, bottom-anchored, and does not auto-scroll when user is reading older messages.
- [ ] Message bubbles cover text, timestamps, sender names for groups, date separators, delivery/read status, deleted/edited/unsupported states where available.
- [ ] Media messages show safe async previews/fallbacks for images, videos, audio, documents, stickers, and captions where supported.
- [ ] Compose box supports sending, multiline input, disabled/disconnected states, send failures, retries, and draft behavior.
- [ ] Read behavior is correct: only mark open chat read when window is focused/visible; unfocused/minimized chats must not be counted read.
- [ ] Notifications are consistent with focus/read state and do not notify for the currently open focused chat.
- [ ] Search/filter supports chats and messages if previous implementation had it.
- [ ] Chat info/details exposes avatar, name, participants/group info, mute/archive/pin/media info where daemon supports it.
- [ ] Error handling is graceful for daemon disconnects, login failures, chat/message load failures, send failures, and media failures.
- [ ] KDE integration is complete: theme colors, icons, shortcuts, accessibility labels, desktop metadata, app id, and no GTK/libadwaita assumptions.
- [ ] Performance stays smooth with large chat/message lists, history sync, reconnects, async avatars/media, and no duplicate gRPC streams.
- [ ] Testing covers real daemon login, already-logged-in startup, disconnect/reconnect, logout, large data, focus/read semantics, narrow/wide layouts, and no QML runtime warnings.
